missiv-client's stores rebuilt on one lifecycle (S3-14). `activeStore` (in `utils/lifecycle.ts`) runs a store's work only while it has subscribers and only for the registration's current account: a change of account stops the run and starts another, the last unsubscription stops it, and a stopped run cannot write the store; `poll` repeats a fetch while the run lives. It replaces the copied `derivedWithStartStopNotifier` and the `running`/`fetching` flags, and fixes what they broke: the conversation list polls again (it fetched once) and counts requests (`numUnaccepted`: not accepted) apart from unread accepted conversations (they were inverted); a conversation closed while fetching stops polling; `markAsAcceptedAndRead` accepts once per newer message instead of on every poll; the room reconnects a lost socket with backoff, with a fresh challenge and a new login, and stops listening to a socket it closed. Every server error reaches the store: a store's `error` carries the server's `code`, `register` and `edit` reject with the `MissivAPIError` and set it, and a room message the room refuses (rate-limited, too long, not logged in, not authorized) is marked `failed` with the room's error instead of staying pending. Breaking: `openOneConversation` takes no `account` (the registration's account is the reader) and its state's `conversationID` is undefined while `Idle`; `ChatUser` is `{address, id}`, one per session; each store takes an optional `fetch`, and `openRoom` a `createWebSocket` and a `reconnectDelayMs`. Room messages carry no `signature` field any more (the server attributes them to the session, ADR-0002), and every room error has a `code`. The demo app's conversation panel sends an introduction in clear only on an explicit button, shows a copy it cannot open as such, and its svelte-check error is fixed; `svelte-check` now runs in missiv-client's build, so the verify fails on a type error.
