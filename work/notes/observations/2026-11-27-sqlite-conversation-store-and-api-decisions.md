# Decisions made while building sqlite-conversation-store-and-api

In-scope choices the task and ADR-0005/0006 left open, one per entry, for the reviewer and the human to ratify or reverse. The wire ones (1 to 6) are what clients will be built against.

1. **Routes**: the send is `POST /api/messages/send` (ADR-0006's `messages/send`); the reads and status changes are `POST /api/private/<action>` (`listMessages`, `listConversations`, `accept`, `reject`, `unblock`, `markRead`), where 0.5's conversation routes were. 0.5's messaging routes (`sendMessage`, `getMessages`, `getConversations`, `getAcceptedConversations`, `getUnacceptedConversations`, `acceptConversation`, `rejectConversation`, `markAsRead`) and the per-copy format (`message-signature.ts`, `encryptedCopies`, `clearCopies`, `openMessageCopy`) are removed. Alternative: every 0.6 route under `/api/messages/`. Site: `packages/server/src/index.ts`, `api/messages/`, `api/private/`.
2. **Bodies keep a `type` literal** like every action but `/session` (`{type: 'sendMessage', message}`, `{type: 'listMessages', ...}`); the send carries the message as `message`, not spread. Site: `packages/common/src/index.ts`.
3. **New error code `stale`, HTTP 400**, `details: {serverTime}` (`StaleDetails`); the window is symmetric (`MESSAGE_ID_WINDOW_MS`, 10 minutes either side of the server's clock). Alternative: 409 like `conflict`, or `invalid_request` with details. Touches `@missiv/client`'s store (it composes again once under `ulidAt(serverTime)`), and `MissivError`'s code list. Site: `ERROR_STATUS` and the send route.
4. **`listMessages` answers in ascending seq order whatever the direction, with `hasMore`** (newer for `after`, older otherwise); neither cursor is the newest page; `after` and `before` together are refused. Alternative: newest first for `before` (0.5's order) or a `cursor` string. Site: `ActionListMessagesSchema`'s JSDoc.
5. **`Conversation` is one member's inbox row**: `status` (`unaccepted` | `accepted` | `rejected`) replaces `accepted: boolean`; `lastSeq`, `lastReadSeq`, `lastMessageAt` replace `lastMessage`, `lastRead`; `user` is dropped; `members` are derived from the conversationID. `listConversations` filters by any of the three statuses; without one it lists all three (as 0.5's `getConversations`). Unread is `lastReadSeq < lastSeq` (`isUnread`). Site: `packages/common/src/index.ts`.
6. **Error codes of a refused send**: a message from another account than the token's, naming another key set, under a key set that is no longer the current one, or with a signature that does not verify, is 403 `forbidden`; a non-member's read or send 403; a conversationID of another form than the 1:1 one (a group's, a malformed one) 400 `invalid_request`; a `pairwise-v1` keyID not naming the sender's keyRef 400. Site: `packages/server/src/api/messages/index.ts`, `api/conversation.ts`.
7. **The sender's own inbox row becomes accepted and read up to its message on every send** (0.5 accepted it and set its `lastRead` to the send's time); the recipient's starts `unaccepted` with `lastReadSeq` 0 and a later message never changes its status or read mark. `accept` no longer marks read (0.5's took `lastMessageReadTimestampMS`): the client store accepts once and calls `markRead {seq}` per newer message. `markRead` clamps to `lastSeq` and never goes back. Site: `INBOX_UPSERT` in `packages/server/src/stores/sql/messaging.ts`.
8. **A hidden message takes a seq** (the recipient sees a gap in the sequence, nothing else), stays hidden after `unblock`, and never creates or moves the recipient's inbox row; the sender's row moves as for any message. A retry is not pushed again. Site: the append's statements.
9. **No `Conversations` table**: the next seq is the conversation's last one read backwards on the `Messages` primary key (`ORDER BY seq DESC LIMIT 1`, not `MAX(seq)`, so the plan is one index step), and the members are the conversationID. Alternative: a conversation row with `lastSeq` (one more write per send). Site: `0002_v0_6_conversations.sql`.
10. **`0002_v0_6_conversations.sql` drops `0001_v0_6`'s message tables** instead of editing `0001_v0_6` in place, so a database made by an unreleased 0.6 build (a local D1, a `file:` libSQL) moves to the new schema instead of silently keeping the old one; it loses its test messages. Site: the file's header.
11. **The send reads the sender's current key set on every send, uncached** (one statement, before the transaction): ADR-0006 says "a cached directory read", but the stores are built per request and a process-wide cache of "current" would have to be invalidated on registration. Alternative: an in-process cache by (domain, keyRef) of the signing key plus the token's keyRef as "current" (no read, but a replaced key set could send for up to the token's hour). Site: the send route's JSDoc.
12. **The server checks a `pairwise-v1` keyID only for naming the sender's keyRef**, not that its other keyRef is the recipient's current key set (0.5 checked each copy's recipient key, at one lookup per member). The client verifies the recipient's key set before encrypting and every reader checks what it decrypts with. Site: the send route.
13. **Ports and seams**: the replay set (`acceptRequestSignature`) is on the `KeyDirectory` port (it lives beside the directory on every platform); `ConversationStore.append` returns the inbox updates it did NOT apply (`pendingInboxUpdates`), which the route applies with `Inbox.update` (the SQL store applies both in its transaction and returns none; Cloudflare's will return them); `pushTo` carries the recipients the append loaded, so a push reads nothing more; `services.getStores` lets a platform supply its own stores (default `createSQLStores(getDB(env))`). Touches `cloudflare-durable-object-stores` and `live-inbox-channel`. Site: `packages/server/src/stores/ports.ts`, `types.ts`.
14. **`@missiv/bun`'s tests run under `bun test`, and `pnpm test` skips them with a warning when bun is absent** (`platforms/bun/scripts/test.mjs`), so a machine without bun still runs the rest; `REQUIRE_BUN=1` makes a missing bun a failure (for CI with bun). The contract suite lives in `packages/server/test/store-contract.ts`, parameterized by the implementation and the runner, imported by `platforms/bun/test/` by path; the Bun platform's boot test imports the client-server tests' users the same way. `createBunServer` was split out of the CLI for it. Alternative: a bun install as a dev dependency (`bun` on npm), which downloads a binary at install.
15. **The load harness's 0.5 adapter is removed** (it spoke an API that no longer exists); `0.6` is the default and `0.6-page` reads the newest page every time, for the comparison with 0.5's reads. 0.6 sends are `clear`, as the 0.5 adapter's placeholder content kept encryption out of the numbers. Site: `test/load/src/adapters/v0-6.ts`.
16. **The client's conversation store fetches the newest page once, then only `after` the last seq it has**, following `hasMore` within one poll; it does not page back older history (no `before` in the store yet). Site: `openOneConversation`'s JSDoc.
17. **`membersOfConversationID` (new in `@missiv/common`) accepts only `getConversationID`'s order** (the greater address first), and `openMessage` now answers `unverified` for a two-address conversationID in the other order (it used to accept either order and check the sender against both). Site: `packages/common/src/index.ts`, `packages/client/src/lib/messages.ts`.
18. **CONTEXT's `inbox` now means ADR-0005's Inbox** (a user's conversation list with unread state), not "the stored set of copies"; `copy` is removed from the glossary and `store ports`, `seq`, `stale`, `status` added. Site: `CONTEXT.md`.
