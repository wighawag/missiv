# sessions-and-tokens: decisions made while building

2026-11-27, task `sessions-and-tokens` (ADR-0004 decision 5, ADR-0006 "Sessions and replay"). These are choices the task and the ADRs left open. Each one is recorded here so a reviewer can ratify or reverse it. The token-format choices are also in the JSDoc of `packages/server/src/session.ts`.

1. **The route is `POST /api/session`**, in its own route group (`packages/server/src/api/session/`). ADR-0006 names `POST /session`, and every route of the API lives under `/api`. Alternative: `/api/user/session`, next to `register`. Rejected because a session is not a user-profile action, and the ADR names it as a top-level route.
2. **The body is `{domain}`, with no `type` field** (`ActionOpenSessionSchema`), as ADR-0006 writes it. Every other action carries a `type` literal. Alternative: `{type: 'openSession', domain}`. Rejected to keep the ADR's wire shape.
3. **A request signature no longer authenticates the token routes**: a signed request with no token gets 401 there. The task says the middleware authenticates from the token on every route except `register` and `sendMessage`. Accepting both would keep a per-request signature check and directory read on routes meant to have none. Touches the S3-6 envelope tests in `test/client-server/test/defects.test.ts`, which now sign `POST /api/session` instead of `getConversations`. `editUser` is now on a token too.
4. **Without `SESSION_SECRET`, every route that authenticates its caller answers 403 `forbidden`**: `/api/session`, the token routes, and also `register` and `sendMessage`. This follows the `ADMIN_TOKEN` precedent (403 "disabled"). The public reads (`getDomainUser`, `getKeySet`, rooms) still answer. Alternative: refuse only the token routes. Rejected because a misconfigured server would then register users who can never read. The check lives in `sessionSecrets` (`packages/server/src/setup.ts`).
5. **Error codes.** A token for another domain is 401 `unauthenticated`, as the acceptance criteria ask, so the client opens a session for the right domain. A signed `/api/session` request whose key is registered in another domain stays 403 `forbidden`, the code a signed request got before this task (`requireSignedAccount`).
6. **Client renewal and retry** (`packages/client/src/lib/API.ts`):
   - A session is renewed when it has less than 5 minutes left (`SESSION_RENEWAL_MARGIN_MS`), measured on the client's clock against the server's `expiresAt`. A client clock that is more than about 55 minutes fast would therefore reopen a session on every call. The retry below covers a clock that is slow.
   - A token refused `unauthenticated` triggers one new session and one retry.
   - Sessions are cached per `API` instance, keyed by domain and signing private key, and only in memory. Each store (`openConversationList`, `openOneConversation`, ...) builds its own `API`, so each one opens its own session.
7. **`openSession` retries once, 2 ms later, when the server answers 409 `conflict`.** delegated-identity's Ed25519 signatures are deterministic, so two `API` instances opening a session for the same key in the same millisecond send byte-identical requests, and the server refuses the second as a replay. This is the limitation recorded for registrations in `2026-11-27-messaging-keys-and-registration-decisions.md`, removed here for sessions. Alternative: put a nonce in the body. Rejected because it changes ADR-0006's `{domain}`.
8. **The platforms' `dev` scripts set a dev-only `SESSION_SECRET` when none is set**: `missiv-dev-only-session-secret`, through `--var` for wrangler and `${SESSION_SECRET:-…}` for nodejs and bun. This keeps the demo stack (`pnpm start`) working. `.env.default` is NOT given a secret, because it ships in the `missiv` and `@missiv/bun` packages and a public default secret would run in production. Alternative: no default at all, documented only. Rejected because the demo would break silently on its first call.

**Limitation (ADR-0004 decision 5's price):** a token issued before its key set was replaced stays valid until it expires (at most an hour), because no request reads the directory. A new session can only be opened with the current key set.
